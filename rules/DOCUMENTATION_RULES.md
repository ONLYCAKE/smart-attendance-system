# Documentation Rules

- Update `docs/API_SPECIFICATION.md` when endpoints/contracts change.
- Update `docs/DATABASE_DESIGN.md` when schema relationships or constraints change.
- Update `docs/ARCHITECTURE.md` when module boundaries or data flow changes.
- Record significant technical choices in `docs/DECISIONS.md`.
- Update `plans/TASKS.md` as tasks move status.
- Keep PRD requirements stable; propose scope changes explicitly instead of silently changing requirements.
- Document model version, license, evaluation findings, and limitations for face recognition.

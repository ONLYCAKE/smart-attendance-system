# Skill: Project Planning

## Purpose
Turn a requirement into a small, testable implementation plan.

## Procedure
1. Read PRD and architecture.
2. Identify dependencies and affected modules.
3. Inspect existing code before proposing changes.
4. Define scope, files likely affected, acceptance criteria, and tests.
5. Update task status and document blockers.
6. Do not start implementation if a required product decision is unresolved.

## Constraints
No unrelated refactors, speculative features, or verbose restatement of the request.
